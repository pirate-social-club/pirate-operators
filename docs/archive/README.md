# Documentation archive

This directory preserves point-in-time documentation that no longer belongs in the active reading surface. It is evidence and provenance, not current product documentation.

The archive is grouped by kind:

- `ci/` — CI audits, compiler reviews, and pull-request repair records.
- `design/` — superseded broad designs, including the pre-November-14 setup plan, the recovered operator protocol, and the old account/protocol portability design.
- `evidence/` — independent reconstruction and public-readback records.
- `handoffs/` — implementation handoffs whose status claims belong to their original lane and date.
- `incidents/` — flake and recovery incident notes.
- `lanes/v1/` — parallel v1 implementation contracts, repair notes, source-correction records, and page inventories.
- `proposals/` — unselected or superseded proposals.
- `study/` — Study/Karaoke rollout, stabilization, activation, and successor coordination records.
- `telegram/` — Telegram implementation and repair lane records.

These files are not maintained for currentness. They may mention removed or deferred scope, old providers, old service-custody decisions, old deployment targets, or old pull-request states. In particular, historical Spaces, Nostr, Telegram, app.tld, creator-wallet, and provider-setup material does not describe current pilot scope.

Do not silently rewrite archived records to make them look current. If a fact remains relevant, move it into a small current document with a fresh review. Cite the archive only as evidence of what was decided, implemented, or observed at that time.

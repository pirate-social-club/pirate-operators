# Categorical Dance verdict source

This source implements the local V5 semantics for the `pirate.dance-verdict/1` family. The semantic packet is identified by SHA-256 `98645e345bbed9a3aeb64ebdd37a18cbfcf65c07c1998605f9459c94275ebd90`. A contract deployment and offer admission are separate reviewed operations. No live Dance source, policy or offer follows from this source checkpoint.

`DanceVerdictsV1` owns the order and state of every command for one community. `DanceCapturePolicyV1` is a stateless verifier, called with `STATICCALL` semantics. The verdict contract pins its address and runtime hash as immutables and checks the hash before each new registration or verdict. The verdict contract's own runtime hash binds both immutables into the source hash. Directory, Posts and V4 runtime pins remain explicit. The Foundry size profile applies to these two Dance contracts; existing contracts retain their default settings.

The Directory controller configures the owner wallet and its bounded validity interval. The owner wallet directly grants or revokes delegates. The current pinned publisher attests authenticated capture, media and reviewer facts. The contract checks epochs, source and policy commitments, current V4 authorization and the canonical song and reference at the position of each transaction. No wallet signature is requested for each verdict. The publisher is a trusted attestor of media, account and reviewer facts that the chain cannot observe.

The ten operations use static, typed ABI preimages and the domain, chain, verdict contract, community, operation, caller and command ID. The two largest commands accept exact-length ABI bytes, decoded as the same static tuples. Registration has 54 words and a verdict has 15. The capture field called `reference` in the semantic packet is named `referenceSelection` in Solidity. Field names are not encoded. Caller-scoped command IDs prevent one caller's unrelated command from reserving another caller's ID. Exact replay returns the first receipt without another event or state change. An existing ID with another payload fails. HTTP recovery must still check current private access.

Registration stores the immutable capture and submission preimages. Media readiness is a separate epoch; cancellation can create a tombstone before registration or withdraw media after a verdict without replacing it. The capture seals the exact V4 authorization before consent and recording. Reauthorization cannot substitute another ID into a previous capture. Private review expires seven days after accepted submission, with an exclusive deadline.

A terminal verdict is Pass or Not passed. The contract records block seconds and whether a Pass was inside the frozen offer's half-open time interval. The reader verifies the receipt-owned log, its canonical transaction position, safe confirmation, historical runtime pins and stored registration before deriving event evidence. It does not reevaluate old authorization using later state. The reward adapter also checks the existing attached-offer input hash, source membership, exact historical song/audio and retained account binding. It never retargets a result into a different offer or invents a numeric score.

The registration and verdict bytes, wallet addresses and commitments are public. Raw local account or media IDs, video, private links and notes are not included. Live disclosure and terms approval, immutable historical account capture, producer/private media mounts, canonical outbox reconciliation, closure snapshot persistence and revalidation, and the full integrated release gates are still required.

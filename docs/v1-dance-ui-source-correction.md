# Established Dance compositions on decentralized ports

This bounded frontend successor starts at ae30f8597bb43fa52111c5f89cf51ae1c43bdb94.
Its only source reference is pirate-web-solid c7cb87835a1858a1955c820b03d566365e6d42db,
read through immutable Git objects. The immutable Storybook export is a second
read-only witness. Existing operator review, backend, shared mounts, styles and
all earlier sealed evidence remain unchanged.

The learner composition is the established song reference grid and selected
reference overlay, original XState recorder journey, full-screen capture and
retained-recording recovery, followed by the established recording review and
result composition. Camera, capture clocks, original recording storage and
playback ownership come from those source modules. This is independently owned
source; no import or runtime request resolves into the reference application.

Private identity comes only from the authenticated profile owner's accountId
producer at 4fb53c074b980fdb8894811404d3270e06618064. Public authorId, wallet and
profile presentation never substitute for that account. The host supplies a
session lifetime and invalidation subscription in addition to account identity.
Changing account, session, song, revision or reference disposes the actor,
aborts requests, stops camera/guide/player tracks and removes private URLs.

V5 reserves the exact capture and consent together before camera acceptance.
The original separate central session-create/consent HTTP protocol cannot be
copied as an API. An explicit source Start gesture calls the admitted Dance
capture command with the displayed admitted consent; recovery keeps the
original command and captured fields. The statechart remains the source
journey, with this preparation port and the source's explicit review submission.
No central persona selection, authentication, API client or localStorage is
used. IndexedDB commits original command/recording metadata before dispatch.

The private upload port delegates to the existing media producer. It receives
the immutable capture, original file/digest and original request ID. Its read
capability cannot replay upload/submit. Unknown reservation, upload or submit
acknowledgements retain the original identity across reload and prohibit a new
recording. Definite cancellation/expiry is distinct and must be established
before a fresh attempt. Local cleanup never claims server withdrawal.

Guide playback must return complete digest-checked canonical song bytes for
the frozen song/revision. Reference and private playback require separate
current access checks; their URLs cannot be persisted in journals. Missing
camera, media, catalogue, authority or playback capability is an honest held
state, not a fixture or optimistic success. Public clips remain 3–15 seconds;
private Dance uses its frozen 6–30 second interval. No public posting control,
visibility command, reward amount or numeric score is enabled by this port.

The result reads canonical evidence separately from local decision intent.
Pending publication cannot render Passed or Not passed. A review expires at
trustedSubmittedAtMs + 604800000, exclusive. Withdrawal clears local playback
immediately and remains pending until canonical acceptance. This is a necessary
departure from the centralized final D1 result/publication contract.

The new local component-interface and route/service proposal specify the host
boundaries before implementation. Coordinator integration later selects only
this frontend delta; it must not merge the held backend branch wholesale.
Exact dependency changes, authenticated-owner production, private byte routes,
catalogue/selected-source capabilities and all shared mounts remain coordinator
proposals. Actual tests, types, Storybook, renders, device/provider acceptance,
independent comparison and release are unrun and coordinator-owned.

The original machine's named actors, routing, deliberate recovery events,
processing substates, 15-second read timeout, 2-second observation interval and
90-read rest remain. Its central authentication error class is replaced by the
owned HTTP denial. ACCESS_LOST explicitly clears actor view/review and playback
ownership. The input is named termsHash for the actual V5 consent preimage;
it is never advertised as a qualification-policy or offer input hash. V5 has no
pose. Existing capture prefix verification, synced video zero, natural microphone
offset and guide interruption remain the original source controllers.

The source's synchronous localStorage capture claim is replaced by committed
IndexedDB metadata and a held Web Lock across camera/take retention. Unsupported
locks/storage fail honestly. add(), digest readback and immutable original
metadata prevent another take replacing a retained file. An accepted original
is archived before a definite reset. A new attempt after submission requires
fresh safely canonical completion; pending publication or an unknown response
cannot clear it. Unavailable historical/private terminal reads remain held.

The existing backend uses distinct exact digest representations: V5 uses
0x-prefixed bytes32, and source3 uses 64 lowercase SHA256 digits. The owned
digests module performs that explicit boundary conversion, including submission
payloads. It never changes old retained command JSON. Capture/sample identities
are not rounded; a sub-millisecond frozen interval which the original
millisecond capture controller cannot represent is refused for integration
review. Recovery of an older consent needs its exact admitted historical copy;
current terms cannot substitute for it.

The same-tree source3 media client is consumed through a versioned adapter,
not copied from mutable peer source. Its server reservation/upload/status/retry
pipeline is unchanged. The adapter adds lifetime cancellation and preserves
plain-text 401/403 before the producer's JSON parser. It sends x-dance-account;
the existing generic media mount does not establish that fence by itself.
The coordinator must implement the proposed authenticated expected-account
check before private reads/body/proof/dispatch. HTML private playback still
requires current cookie/session and Dance access on each GET/HEAD/range.

The required captureAccess port compares the whole original capture against
the server's immutable reservation and rechecks its exact current authority;
it is required before camera/guide acceptance and pre-submission review access.
No production implementation silently supplies success. Its route, catalogue,
reference/guide access, source trust and private-byte assembly remain explicit
coordinator gates. These checks do not solve canonical ordering races or
the authority/media commit problem; the held verified backend owns those facts.

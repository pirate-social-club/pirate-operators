# Signed Linux create-only profile V3

This source milestone implements the proof-qualified one-host create path with `pirate.community-linux-profile/3` and settings
version 3, mode `create`, target `{kind:"local-linux"}`. Run setup on that Linux
host; a VPS can expose the paired operator browser through authenticated
forwarding. Hosting an HTTPS origin does not establish controlled-TLD authority.
The original namespace proof, shared Directory/configuration, explicit Linux to
Directory installation mapping, portable community key and retained resource
identities remain required on this path.

The current owner direction also requires usable HTTPS setup while HNS
verification is pending. That state is not representable by the current closed
profile, Directory/configuration and authority ports. Its joined representation
remains open with the owning Directory/HNS lanes. This milestone is not the
final HTTPS-first setup contract. No proof is fabricated, no existing guard is
removed, and no listing, TLD badge or member issuance is inferred while pending.

Settings contain public IPFS media and private local persistent data. They omit
backup storage and recovery/session-policy fields. Guided import, encrypted
archive restoration and automated upgrade are deferred for this schema. The
existing V2 codec, signed originals, archive/import/restore paths and tests remain
separate. A V2 installation is never relabelled or converted into V3.

A reviewed automated issuer can supply these genuine inputs; the wizard adds no
manual staff approval step. The managed issuer signs the entire new profile digest through the existing
admission envelope. The separate signed `pirate.linux-create-template/1` binds
actual settings, identity, runtime, selected Learning and infrastructure before
namespace proof. Signing requires the actual managed key agent; the returned
body must exactly match. Current signed policy must approve the exact V3 digest.
A prior V2 digest approval grants no authority to the changed schema. Actual
source/artifact/migration, host, resource, fresh namespace, current policy and
custody checks remain required after the established asynchronous boundaries.

An unsigned `pirate.linux-create-runtime/1` document selects installed paths and
ports only. The exact installed TypeScript composition calls the existing
`bootstrapLocalTarget`; there is no second server or successful fallback.
The create constructor remains owned by the Linux backend lane. Missing genuine
keys, source selection, authority, credentials, bootstrap, producer or resource
inputs must refuse construction or remain unavailable.

Capabilities remain version 2. The create delivery advertises only a local
create operation, no backup formats/profiles/session policies, no SSH target
and zero ciphertext capacity. Deferred operations refuse before key-owner calls
or byte consumption. Saved credentials are not readiness.

V3 plans require action `create`, null session policy, null predecessor and null
restore inspection/manifest/ciphertext fields. A started, unknown or failed
original cannot authorize a reset or retry child. Reconciliation preserves its
immutable signed profile, request, intent, resource identities, raw receipt and
bounded journal evidence. Ordinary restart uses the same persistent installation.

The V3 source includes prepared codec/signature, managed-producer/current-policy,
real D1 initializer/login-handler recreation and disk-journal restart/no-replay
regressions. They are unrun at this handoff. The genuine native scenario consumes
actual authenticated constructor inputs and reuses the production bootstrap,
create/readback and restart paths; it requires a separately allocated native
resource window. Unit/model cases do not establish browser, Linux host, external
namespace, provider, media publication, funds or release acceptance. Existing
browser cases and broader deferred recovery evidence remain retained.

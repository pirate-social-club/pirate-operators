# Shell source custody and provenance

Lane 1 accepts source custody for the admitted shell worktree. The coordinator
captured the earlier `pirate-community-app-shell-dance-20261110` draft, verified
its manifest, restored the old checkout and parked it through the lifecycle.
The retained input is the `parallel-execution/old-shell-draft` packet dated
2026-11-10, base `694ca90a1639b331fdb2889984d4f246992195e2`.

The earlier `app-shell.tsx` contributes the explicit-props sidebar/header/footer
composition and native fragment route idea. Its draft `entry.tsx` is not copied;
the newer `67cbe11` entry is edited incrementally, preserving its sign-in
settlement, account-keyed Study, publication permission and payment mounts.
The captured test is inspected as historical input. Its missing stylesheet,
invalid `tabIndex`, skip-link route collision and incomplete browser history
are resolved in the independently owned implementation. The capture remains
unaccepted historical evidence, not a build baseline.

Design references are the pure Solid components at pirate-web-solid
`c7cb87835a1858a1955c820b03d566365e6d42db`:

- `src/features/shell/app-sidebar/app-sidebar.tsx`
- `src/features/shell/app-shell-chrome/app-shell-chrome.tsx`
- `packages/solid-ui/src/patterns/navigation/mobile-footer-nav/mobile-footer-nav.tsx`
- `src/features/community/page-shell/page-shell.tsx`

The independently owned adaptation retains the 15.5rem sidebar, token-based
navigation states, top-right account access, community page composition,
mobile bottom navigation and safe-area spacing. Existing vendored Solid UI
provides icons and tokens. Session providers, personas, centralized clients,
membership/social controls and provider runtimes are excluded. There is no
runtime import or build link to the reference checkout.

On 2026-11-10 this lane also read the connected Pirate Design System Paper
file's Screens/Community/CommunityPage and Patterns/Navigation/MobileFooterNav
JSX and inspected the mobile community screenshot. Its token content hash was
`6d78f570`: neutral dark surfaces, 768px mobile breakpoint and 64px footer.
The implementation uses those existing tokens and geometry. Rendered desktop
and mobile fixture screenshots were inspected for spacing, hierarchy, contrast,
alignment and viewport fit. The adaptation intentionally includes only working
destinations and data; it does not invent the reference's Follow/Join,
notifications, banner imagery or social counts. This is a reviewed adaptation,
not a claim of pixel parity or physical-device acceptance. No Paper design was
modified by this lane.

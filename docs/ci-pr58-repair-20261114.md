# PR58 CI repair, November 14

This repair follows the Web2 plan published at `a163fc1`. It preserves the
existing test assertions and all six required CI suites. No contract,
dependency, schema or deployment change belongs to this repair.

## Causes and corrections

The [plan-publication CI run](https://github.com/pirate-social-club/pirate-operators/actions/runs/43627799138)
failed 46 live-browser cases because four older HTTP fixtures rejected the
membership controller's authenticated `GET /api/community/join`. The fixtures
now explicitly report an unjoined account. They reject membership writes and
anonymous reads. The desktop chrome scenario explicitly supplies an existing
member's receipt because its unchanged assertion requires the member Post
button. These are simulated HTTP responses, not membership issuance evidence.

The [earlier source run](https://github.com/pirate-social-club/pirate-operators/actions/runs/43622708120)
also exposed three SQLite adapters without `withSession`. Native business
capture now queries the primary schema through that interface. The adapters
delegate sessions to their existing actual SQLite connection, preserving SQL,
transaction and fault-injection behavior. They do not simulate D1 replication
or manufacture native proof rows.

Linux filesystem tests require a private temporary directory and a private
parent under `/run`. The root shard command supplied neither. It now creates
fresh private directories inside the existing root-owned network namespace.
Directory creation fails before the test command if setup fails. The tests'
ownership, path, permission and negative assertions remain unchanged.

The existing captured-policy leasing test found a production SQL bug. For a
stored job without a policy field, the new catalog-policy exclusion evaluated
to SQL NULL and prevented leasing. Coalescing absent policy values restores
the sequence already defined by `jobSteps`. Exact catalog and unregistered
policy exclusions, due-time checks and lease checks remain in force. Final
publication had a second missing-policy dereference. The catalog completion
obligation now applies to the catalog's final step, after the captured sequence
check, while older sequences can finish normally.

The existing withdrawal race intercepted only a single statement's execution.
Lesson creation now atomically batches that statement with native capture. The
test now intercepts actual persistence through either direct or batch execution,
including sessions, and passes the original prepared statements to D1. It still
requires withdrawal to happen, a 409 response and a privately closed lesson.
The database is restored even if the request throws.

The [first hosted successor](https://github.com/pirate-social-club/pirate-operators/actions/runs/43643319760)
at `ede1629` passed every suite job except one stale-readback case in root
shard 1. The aggregates correctly remained failed. That case used a
five-millisecond sleep to assume its old observer had started. Concurrent
reconciliation deliberately shares one active read, so an actually delayed
observer timed out instead of permitting the test's concurrent newer read.
An explicit entry handshake reproduced the hosted failure locally.

The corrected case waits for entry, uses the existing bounded reconciliation
timeout, obtains the newer terminal observation and then releases the late old
response. The entry handshake also fails if reconciliation ends without entering
the observer. All previous success and revision assertions remain; intermediate
unknown state and persisted terminal state are additionally checked. No product
deadline changed. All 16 Wizard flow cases and the root typecheck pass.
